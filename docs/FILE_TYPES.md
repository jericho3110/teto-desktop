## The three ways files are used

| Kind | Who writes it | Committed? | Examples |
| --- | --- | --- | --- |
| **Source** | you | yes | `.go`, `.rs`, `.ts`, `.cs`, `.svg` |
| **Configuration** | you (sometimes a tool) | yes | `package.json`, `Cargo.toml`, `tauri.conf.json`, `.gitignore` |
| **Generated** | a tool, from source | **no** (listed in `.gitignore`) | `.class`, `.exe`, `.wasm`, `bin/`, `obj/`, `node_modules/`, `gen/schemas/` |

Rule: if a tool can regenerate it from what's committed, don't commit it.
Exceptions are **lock files** (see below): generated, but committed on purpose.

## Data and configuration formats: JSON, TOML, YAML

Three text formats for structured data. Same idea (keys, values, lists,
nesting), different syntax and trade-offs.

```json
{ "name": "teto-desktop", "private": true, "scripts": { "dev": "vite" } }
```

```toml
[package]
name = "teto-shell"
edition = "2021"

[dependencies]
tauri = { version = "2" }
```

```yaml
name: teto-desktop
private: true
scripts:
  dev: vite
```

| | JSON | TOML | YAML |
| --- | --- | --- | --- |
| Full name | JavaScript Object Notation | Tom's Obvious Minimal Language | YAML Ain't Markup Language |
| Comments | **no** | yes (`#`) | yes (`#`) |
| Nesting by | braces `{}` `[]` | `[section]` headers | **indentation** |
| Strictness | very strict (no trailing commas) | strict, explicit types | flexible, so it has surprises (YAML 1.1 parsers, still common, read `no` as `false`) |
| Used here by | npm, TypeScript, Tauri, skins, Claude's protocol | Cargo (Rust) | not used (yet), see below |
| Best for | data exchanged between programs | config files humans edit | config with lots of nesting (CI pipelines, Docker Compose) |

**Why JSON is everywhere:** every language reads it (Go `encoding/json`,
Python `json`, C# `System.Text.Json`, JS natively), so it's the common
tongue between our nine languages. Its weakness, no comments, is why
Rust's ecosystem chose TOML for hand-edited config.

## Every JSON file in the project

| File | Read by | What it is |
| --- | --- | --- |
| `assets/skins/teto-chibi/manifest.json` | `typescript/ui/src/skin.ts` | **the skin's contract**: which SVG element ids are her head, eyes, mouth, drills…, and what each face looks like. Field-by-field reference: [assets/skins/README.md](../assets/skins/README.md) |
| `typescript/ui/package.json` | npm | the JS/TS project: name, `scripts` (`npm run dev`), `dependencies` / `devDependencies` |
| `typescript/ui/package-lock.json` | npm | the **lock file**: exact versions of every package installed |
| `typescript/ui/tsconfig.json` | `tsc` | TypeScript compiler options (`strict`, target, module resolution) |
| `cpp/physics/package.json` | npm | here npm is only a **task runner** (`npm run build` → clang); no dependencies |
| `rust/shell/tauri.conf.json` | Tauri (at build time, via `generate_context!`) | the app: window size/transparency/always-on-top, dev and build commands, **Content Security Policy** |
| `rust/shell/capabilities/default.json` | Tauri | **permissions**: which Tauri APIs the web UI may call (drag, focus, click-through). Anything not listed is refused |
| `rust/shell/gen/schemas/*.json` | your editor (generated by `tauri-build`, not committed) | **JSON Schemas** describing what's valid in `tauri.conf.json` and capability files. The `"$schema"` line at the top of those files points here, so VS Code can autocomplete and underline mistakes |
| `typescript/ui/public/quirks/index.json` | `quirks.ts` (generated by `sync-assets.ts`) | the list of quirk files to load |

### What's a "manifest"?

A **manifest** is a file that describes a package of other files: what's
in it and how to use it. `manifest.json` describes a skin folder, just
as `package.json` describes an npm package, `Cargo.toml` a Rust crate, or
`.csproj` a .NET project. The code reads the manifest instead of
hard-coding names, so the contents can change without changing code.

### What's a JSON Schema?

A JSON document that describes the *shape* of other JSON documents
("`width` must be a number", "`label` is required"). Editors use it for
autocomplete and validation. `"$schema": "../gen/schemas/desktop-schema.json"`
at the top of `capabilities/default.json` is that link.

## Project and dependency files (one per toolchain)

Every toolchain has its own "this folder is a project" file. They all
answer the same questions: *what's this called, what does it depend on,
how is it built?*

| File | Language | Toolchain | Notes |
| --- | --- | --- | --- |
| `go.mod` | Go | `go` | module path (`github.com/jericho3110/teto-desktop/brain`) + Go version. Lists dependencies too, but we have none, so there's no `go.sum` (Go's lock/checksum file) |
| `Cargo.toml` | Rust | Cargo | package name, `[dependencies]`, `[build-dependencies]` (used only by `build.rs`), `[lib]` crate types, `[profile.release]` optimization settings. TOML format |
| `package.json` | TS/JS | npm | see above |
| `Teto.Companion.csproj` | C# | MSBuild / `dotnet` | XML. `TargetFramework` (`net10.0-windows`), `OutputType` (`WinExe` = GUI app), `PackageReference` (NuGet dependencies), compiler settings like `TreatWarningsAsErrors` |
| `Teto.Companion.Tests.csproj` | C# | MSBuild | the test project; `ProjectReference` points at the companion |
| `Teto.slnx` | C# | `dotnet`, Visual Studio | a **solution**: a list of projects built together. `.slnx` is the newer XML format replacing the old text `.sln`; `dotnet test Teto.slnx` builds and tests both projects |
| *(none)* | Java | `javac` | we compile by hand; bigger Java projects use Maven's `pom.xml` or Gradle's `build.gradle(.kts)` |
| *(none)* | C | `clang` | the command line is the build; bigger C projects use `CMakeLists.txt` or a `Makefile`. In the app, Rust's `build.rs` compiles it |
| *(none)* | Python | `python` | stdlib only; a packaged project would have `pyproject.toml` (TOML again) |
| `build.rs` | Rust | Cargo | not config but code: a Rust program Cargo runs *before* building the crate (here: compile the C module) |

## Lock files

A lock file records the **exact** version of every dependency, including
dependencies of dependencies, that was used. Committing it means everyone
(and every future you) builds with identical versions.

| File | For |
| --- | --- |
| `typescript/ui/package-lock.json` | npm packages |
| `rust/shell/Cargo.lock` | Rust crates (pins `tauri 2.12.1`, which has a security fix) |
| `go.sum` (absent) | Go would create it if we had dependencies |
| `packages.lock.json` (not used) | .NET can do this too with `RestorePackagesWithLockFile` |

`package.json` says "Vite `^8.0.16`" (any compatible 8.x); the lock file
says "exactly 8.0.16". Update deliberately with `npm update` / `cargo update`.

## Source code files

| Extension | Language | Notes |
| --- | --- | --- |
| `.go` | Go | `_test.go` files are tests, compiled only by `go test` |
| `.py` | Python | `test_*.py` are found by `unittest discover` |
| `.rs` | Rust | `main.rs` = binary entry, `lib.rs` = library root |
| `.c` / `.h` | C | `.c` = implementation, `.h` = **header**: declarations other files `#include` |
| `.cpp` / `.hpp` | C++ | same split; `.hpp` marks a C++-only header (templates usually live entirely in headers) |
| `.ts` | TypeScript | compiled (types stripped) to JavaScript |
| `.d.ts` | TypeScript | **declaration file**: types only, no code. `vite-env.d.ts` tells TypeScript about Vite's `import.meta.env` |
| `.test.ts` | TypeScript | tests run by `node --test` |
| `.js` | JavaScript | the quirks; module type decided by the nearest `package.json` (`"type": "module"`) |
| `.mjs` | JavaScript | always an **ES module**, whatever `package.json` says (`.cjs` = always CommonJS) |
| `.java` | Java | one public class per file, file name = class name, folder = package (`teto/reminders/`) |
| `.cs` | C# | file names needn't match classes, but we keep them matching |
| `.svg` | (XML) | vector graphics. Teto's art is an SVG, which is text, so it diffs in git and is generated by Python |

## Build output (generated, never committed)

| Path / extension | Made by | What it is |
| --- | --- | --- |
| `go/brain/bin/teto-brain.exe` | `go build` | Windows executable (`.exe` = Portable Executable format) |
| `java/reminders/out/**/*.class` | `javac` | **Java bytecode**, run by the JVM (`java -cp out ...`). `ReminderServer$Refused.class` = the nested class `Refused` inside `ReminderServer` (`$` separates outer/inner) |
| `csharp/**/bin/` | `dotnet build` | the built program: `TetoCompanion.exe` + `.dll`s (.NET assemblies holding IL bytecode) + `.pdb` (debug symbols) + `*.runtimeconfig.json` |
| `csharp/**/obj/` | `dotnet build` / restore | intermediate files: NuGet restore results (`project.assets.json`), generated source (e.g. the regex source generator's output), incremental-build caches |
| `cpp/physics/dist/physics.wasm` | `clang --target=wasm32` | **WebAssembly** binary module |
| `c/win32hooks/build/*.exe` | `clang` | the C test program |
| `%LOCALAPPDATA%\Teto\cargo-target\` | `cargo` | Rust build output (`target/`), kept outside OneDrive on purpose |
| `rust/shell/gen/schemas/` | `tauri-build` | JSON Schemas for editors (see above) |
| `typescript/ui/node_modules/` | `npm install` | downloaded packages (hundreds of folders) |
| `typescript/ui/public/` | `sync-assets.ts` | copies of skins, quirks and `physics.wasm` for Vite to serve |
| `typescript/ui/dist/` | `vite build` | the bundled production UI |
| `typescript/vscode/out/`, `media/` | `npm run build` | compiled extension, bundled webview, copied skin and wasm |
| `%LOCALAPPDATA%\Teto\vsix\*.vsix` | `npm run package` | the VS Code extension package: a zip with `extension.vsixmanifest`, `[Content_Types].xml` and `extension/` |
| `__pycache__/*.pyc` | Python | cached **bytecode** of imported modules, so imports are faster next time |
| `.lib`, `.obj`, `.pdb`, `.dll` | MSVC/clang | static libraries, object files, debug symbols, dynamic libraries |

## Git's own files

| File | What it does |
| --- | --- |
| `.gitignore` | patterns of files git should **not track** (build output, `node_modules/`, secrets like `.env`, logs). `rust/shell/.gitignore` adds Rust-specific ones. A pattern ending in `/` matches folders; `**` matches any depth |
| `.gitattributes` | per-path **attributes**: ours says `* text=auto` (store text files with LF line endings in the repo; check them out with your platform's endings) and marks `*.png`, `*.wasm` as `binary` (never touch their bytes, don't try to diff them). That's why git printed "LF will be replaced by CRLF": Windows uses CRLF (`\r\n`), Linux/macOS use LF (`\n`) |
| `.git/` | the repository database itself (history, branches). Never edit by hand |

## Documentation and legal

| File | What it is |
| --- | --- |
| `.md` | **Markdown**: plain text with light formatting (`#` headings, `\|` tables, `` ` `` code) that GitHub renders |
| `README.md` | the front page of a folder; GitHub shows it automatically |
| `CHANGELOG.md` | what changed per version ([Keep a Changelog](https://keepachangelog.com/en/1.1.0/)) |
| `LICENSE` | the terms others may use the code under (MIT here). No extension by convention; GitHub detects it |

## Exercises

1. Open `rust/shell/capabilities/default.json` in VS Code and add a typo
   to a permission name. What underlines it, and where does that knowledge come from?
2. Delete `java/reminders/out/` and rebuild it with `javac`. Which
   `.class` files appear for `ReminderServer.java`, and why more than one?
3. Write the `manifest.json` `physics` block in TOML and in YAML. Which do you find easiest to read?
4. Self-check: why is `Cargo.lock` committed but `target/` isn't?
