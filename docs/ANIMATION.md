# How Teto is animated

Everything that moves: how her eyes follow your mouse cursor, how she
blinks, breathes, talks, tilts her head and waves, how her drills swing,
and how particles are drawn. Every number here is taken from the code
(`typescript/ui/src/animator.ts`, `face.ts`, `skin.ts`, the skin manifest,
`cpp/physics`, `rust/shell/src/lib.rs`).

## The big idea: one frame at a time

Animation is a fast slideshow. About 60 times a second (more on a 144 Hz
screen) the browser calls our `frame(now)` function just before it
repaints. Each call answers one question: **"given the time now and
what Teto is doing, where should every part be?"** It then writes that
pose into the SVG. Nothing "plays" on its own; every movement is a formula
of time.

```text
requestAnimationFrame ──► Animator.frame(now) ──► pose numbers ──► Skin ──► SVG attributes ──► browser paints
        ▲                                                                                              │
        └──────────────────────────── next screen refresh ◄────────────────────────────────────────────┘
```

## How the art is built to be animated

The SVG (`assets/skins/teto-chibi/teto.svg`, generated by
`python/skin_gen/gen_teto.py`) is made of **named groups** (`<g id="...">`):

| Technique | Example | Lets us… |
| --- | --- | --- |
| a group per movable part, with a pivot | `#head` (pivot 150,200), `#arm-L`, `#ahoge` | rotate one part with `transform="rotate(deg px py)"` |
| groups inside groups | the eyes and mouth are inside `#head` | tilting the head carries the face along for free |
| **nested** chains | `drill-L-0` contains `drill-L-1` contains … `drill-L-6` | rotating joint 2 bends everything below it, like a real chain |
| state variants, one visible at a time | `.eyes-open`, `.eyes-closed`, `.eyes-happy`, `.eyes-half` | swap expressions by toggling `display` |
| a movable inner group | `.look` (irises + highlights) inside each eye | slide the irises without moving the eye white |
| effect overlays | `#fx-sweat`, `#fx-zzz`, … | show/hide per expression |

`skin.ts` is the only code that knows these ids; the manifest
([assets/skins/README.md](../assets/skins/README.md)) maps them to roles.

## The frame loop, step by step

`Animator.frame(now)` in order:

1. **dt**: seconds since the last frame (clamped, see below).
2. **Blink timer**: if it's time, close the eyes for 130 ms and schedule the next blink.
3. **Face**: `currentFace(mind)` picks the expression (state machine below).
   If it changed, start/stop particle effects.
4. **Particles**: step the C++ simulation and draw the canvas.
5. **Eyes, mouth, blush, effect overlays** from the expression (+ blink/talk).
6. **Head**: breathing bob + sway + smoothed tilt and drop.
7. **Hop** (excited) moves the whole character.
8. **Ahoge** wiggle; faster while thinking.
9. **Arms**: smoothed raise + sway; the right arm waves for reminders.
10. **Eyes look** toward the cursor (or up while thinking).
11. **Hair physics**: feed the head's acceleration to C++, apply the joint angles.

## Time: dt, and why it's clamped

```ts
const dt = Math.min((now - this.last) / 1000, 1 / 20);
```

Every motion is computed from **elapsed time**, not "per frame", so Teto
moves at the same speed on a 60 Hz and a 144 Hz monitor. If the window
was hidden or the PC stalled, `now - last` could be several seconds; one
giant step would teleport parts and make the physics explode. So `dt` is
capped at 1/20 s: after a stall she just resumes smoothly.

## Smoothing: `approach()` and half-lives

Instead of jumping to a new target (e.g. head tilt 11° when confused),
values **ease** toward it:

```ts
// face.ts
approach(current, target, rate, dt) = target + (current - target) * Math.exp(-rate * dt)
```

Each frame the *remaining gap* shrinks by the factor `e^(-rate·dt)`.
After one second, a fraction `e^(-rate)` of the gap is left, whatever the
frame rate (a test pins this). A handy way to read `rate` is the
**half-life**: the time to close half the gap = `ln 2 / rate`.

| What | rate | half-life | feel |
| --- | --- | --- | --- |
| eyes following the cursor | 10 | 69 ms | quick but not twitchy |
| arms raising | 8 | 87 ms | snappy |
| head tilt / head drop | 6 | 116 ms | soft, a bit lazy |
| hair's input acceleration | 25 | 28 ms | only filters jitter |

**Why not `current += (target - current) * 0.1`?** That moves 10% *per
frame*: on 144 Hz it converges 2.4× faster than on 60 Hz. The exponential
form depends only on elapsed time.

## Oscillation: sine waves for "alive" motion

A perfectly still character looks dead. Small, slow, *periodic* motions
make her look alive. Each is `amplitude × sin(ω × seconds)`; the period
(seconds per cycle) is `2π / ω`.

| Motion | Formula (s = seconds) | Period | Amplitude |
| --- | --- | --- | --- |
| breathing bob | `sin(2.1 s) × 1.6` | 3.0 s | 1.6 SVG units up/down |
| breathing while asleep | `sin(0.9 s) × 2.5` | 7.0 s | slower, deeper |
| head sway | `sin(0.7 s) × 1.5` | 9.0 s | ±1.5° |
| ahoge wiggle | `sin(3 s) × 4` | 2.1 s | ±4° |
| ahoge while thinking | `+ sin(7 s) × 12` | 0.9 s | ±12° extra |
| arm sway | `sin(1.3 s) × 2` | 4.8 s | ±2° |
| wave (reminders) | `-95 + sin(12 s) × 25` | 0.52 s | ±25° around -95° |
| hop (excited) | `-abs(sin(9 s)) × 10` | 0.35 s | 10 px up, bouncing |

The periods are deliberately **unrelated** (3.0, 9.0, 2.1, 4.8 s), so the
combined motion never visibly repeats. `abs(sin)` makes the hop: the sine
wave folded upward is a bounce that always lands on the ground.

## Eye tracking: from your mouse to her irises

Five languages are involved in making her eyes follow your mouse:

```text
 your mouse
    │  Windows knows the cursor position (physical screen pixels)
    ▼
 C    teto_cursor_pos(&x, &y)            GetCursorPos               c/win32hooks/src/teto_win32.c
    ▼
 Rust native::cursor_pos()  every 33 ms  (≈30 times/s)              rust/shell/src/native.rs
      x_css = (x - window.left) / scale   → window-relative CSS px   rust/shell/src/lib.rs
      only if it moved: emit "native://cursor" {x, y}
    ▼
 TS   main.ts: animator.cursor = {x, y}                              typescript/ui/src/main.ts
    ▼
 TS   Animator.updateLook() every frame                              typescript/ui/src/animator.ts
    ▼
 TS   Skin.look(dx, dy): <g class="look" transform="translate(dx·3, dy·3)">   typescript/ui/src/skin.ts
```

**Why not just use the browser's `mousemove`?** The window is
click-through: while the mouse is over the transparent parts (and when it's
outside the window entirely), the webview receives **no** mouse events. The
OS always knows where the cursor is, so we ask it via C.

**The math** (`updateLook`):

```ts
const fx = r.left + r.width / 2, fy = r.top + r.height * 0.42;   // her face centre
const dx = cursor.x - fx, dy = cursor.y - fy;                    // vector face → cursor
const d = Math.hypot(dx, dy) || 1;                               // its length (never 0)
const reach = Math.min(1, d / 250);                              // close cursor → smaller glance
tx = (dx / d) * reach;  ty = (dy / d) * reach;                   // unit direction × reach
lookX = approach(lookX, tx, 10, dt);                             // ease (half-life 69 ms)
skin.look(lookX, lookY);                                         // irises move lookX·3, lookY·3
```

1. **Direction:** dividing the vector by its length gives a **unit vector**
   (length 1) that only says *which way*.
2. **Reach:** beyond 250 px she looks fully in that direction; nearer,
   the glance is smaller. Without this, a cursor 1 px from her nose would
   make her eyes snap all the way to the side.
3. **Range:** the result is in −1…1 and is multiplied by `lookRange`
   (3 SVG units, from the manifest), so the irises never leave the eye whites.
4. **Smoothing** makes the eyes glide instead of jumping with each 33 ms update.

**Worked example** (window 360×640, Teto's box at left 45, top 236, 270×360):
face centre = (45 + 135, 236 + 0.42·360) = **(180, 387)**. Cursor at
**(380, 287)** (to her right, above her head, even outside the window):
dx = 200, dy = −100, d = 223.6, reach = 223.6 / 250 = 0.894,
tx = 200/223.6 × 0.894 = **0.80**, ty = −100/223.6 × 0.894 = **−0.40**.
Her irises slide **2.4 units right, 1.2 units up** (in SVG units; ×0.9 on screen).

**While thinking** she ignores the cursor and looks up-right (0.4, −1):
the classic "hmm" glance.

## Coordinate spaces

The same point has different numbers in different spaces. Converting
between them correctly is half of graphics programming:

| Space | Units | Example | Converted by |
| --- | --- | --- | --- |
| screen, physical | real pixels, origin at the top-left of the primary monitor | `GetCursorPos` | Windows |
| window, physical | pixels from the window's corner | `cursor − inner_position` | Rust |
| window, CSS | "logical" pixels: physical ÷ scale (1.25 at 125% scaling) | `native://cursor` payload | Rust (`/ scale`) |
| SVG user units | the `viewBox` (300×400) | `pivot: [150, 200]` | the browser maps viewBox → 270×360 CSS px (×0.9) |
| a group's local space | relative to its parent's transform | drill joints | nested `transform`s compose |
| wasm memory | byte offsets | `fx_field(1)` | JS typed-array views |

## Faces: the little state machine

`face.ts: currentFace(mind)` turns what Teto is doing into one face, by priority:

```text
sleeping?  ──yes──► "sleeping"
   │no
fresh emotion (not expired)?  ──yes──► that emotion (happy, sad, smug, …)
   │no
talking (text arriving)?  ──yes──► "neutral" (so the mouth can flap)
   │no
thinking (brain busy)?  ──yes──► "thinking"
   │no
"neutral"
```

The `Mind` record holds plain values (`thinking`, `talkingUntil`,
`emotionUntil`, …) and the decision is a **pure function**, so
`face.test.ts` checks it without a browser. Emotions last
`2.5 s + 4 s × intensity` (stronger moods linger).

## Blinking

People blink every 2–6 seconds, irregularly. So after each blink the next
one is scheduled at a **random** gap: `2000 + random × 4000` ms. A blink
closes the eyes for 130 ms. Only *open* eyes blink: the happy `^^` eyes
are already closed-looking (a test checks this).

## Talking: mouth flaps

Each text chunk streaming in from the brain calls `animator.talk()`, which
sets `talkingUntil = now + 260 ms`. While that's in the future, the mouth
alternates every 90 ms between the open "talk" shape and the
expression's own mouth (`Math.floor(now / 90) % 2`), about 5.6 flaps a
second, which reads as speech. When text stops arriving, she stops talking
260 ms later: the timeout *is* the "end of sentence" detector.

## Head, ahoge, arms, hop and wave

| Part | Rotation / offset each frame |
| --- | --- |
| head | `rotate(tilt, 150, 200)` + `translate(0, bob + drop)`; tilt = expression tilt + sway, smoothed |
| ahoge | `rotate(expr.ahoge + wiggle, 150, 64)`: droops (−25°) when sad, perks up when excited |
| left arm | `rotate(arms + sway)`; `arms` eases to the expression's value (55° when excited) |
| right arm | mirror of the left, or the wave formula while a reminder is announced |
| whole character | `translateY(hop)` via CSS on the container (excited) |

Rotations happen around a **pivot**: `rotate(θ, px, py)` = move the pivot
to the origin, rotate, move back. The head pivots at her neck (150,200),
so tilting looks natural instead of spinning around her nose.

## Hair physics

Each drill is a chain of 7 joints simulated in C++ (WebAssembly). Every
frame the animator works out how the **head accelerated** (window
dragging, the breathing bob, head tilt shifting the drill roots sideways),
smooths it, and passes it in; C++ returns 7 joint angles per drill, which
`skin.poseChain` writes as `rotate(−θ)` into the nested groups. Details:
[cpp/docs/ARCHITECTURE.md](../cpp/docs/ARCHITECTURE.md).

```text
acceleration = (velocity now − velocity last frame) / dt
velocity     = (position now − position last frame) / dt
```

(Differentiating position twice is noisy, which is why the acceleration is
smoothed with rate 25.)

## Particles

Sparkles, hearts, sweat drops and Zzz's are simulated in C++ (an object
pool in wasm memory) and painted by `fxlayer.ts` on a transparent
`<canvas>` above her, reading the C++ arrays directly. They start when the
face **changes** (excited → sparkle burst, worried → a sweat stream,
asleep → drifting Zzz), not every frame. Details:
[docs/MEMORY.md](MEMORY.md#c-raii-arenas-pools-and-data-layout).

## Click-through and dragging

- **Click-through:** for each cursor update, `document.elementFromPoint(x, y)`
  asks the browser what's under the cursor. Only things marked
  `data-solid` (her painted pixels, the bubble, the bar) count. If the
  answer changes, Rust's `setIgnoreCursorEvents` is toggled. SVG shapes use
  `pointer-events: visiblePainted`, so the transparent gaps between her
  drills are clickable *through*.
- **Dragging vs clicking:** on mouse-down we remember the spot; if the
  pointer moves more than 4 px, it's a drag (`startDragging()` hands the
  move to Windows), otherwise it's a click (a poke: drills bounce, bar toggles).

## Performance

Per frame Teto changes about 40 SVG attributes and clears and draws one
small canvas. Changing a `transform` doesn't affect layout, so the browser
only repaints. Expressions are switched with `display` only when the state
actually changes (`setEyes` returns early otherwise), and the cursor is
only sent from Rust when it moved.
